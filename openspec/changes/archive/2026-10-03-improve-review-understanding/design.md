## Context

The overview is generated by the same model that writes `final.md`, from PR text that may be untrusted. The posted-state half needs a durable record that survives dashboard restarts and drives list freshness.

## Decisions

- **Overview lives in `final.md`, not a new file.** The dashboard already renders `final.md`; a new artifact would need a manifest entry and sync. Rejected: a separate `overview.md` (more plumbing for one section).
- **Placed before `## Verdict`.** Readers get context first. Safe for parsers: `parseFinalMd` matches the verdict, counts and `##` section headings anywhere, and the overview has none of those. A test pins this.
- **Never posted.** The translation command lists the section and any diagram among things not to carry. The human review stays free of tooling and diagram syntax.
- **Mermaid `strict` for markdown, `loose` for the map.** Diagram text derives from untrusted PR content, so click handlers and HTML labels stay off. The map needs `click`, so its security level is a prop, not a global. Rejected: one global level (either breaks the map or weakens markdown).
- **Lazy-loaded.** Mermaid is ~2MB; it loads only when a document contains a diagram. A render error shows the source in a code block plus the error text, so a broken diagram never hides content.
- **Posted state on `review_rounds`.** Posting is per round. `posted_state` stores the state actually sent (after any own-PR downgrade). Failure to record is logged and never fails the post: the review is already on GitHub.
- **Focus refetch only for session queries.** Overriding the global default for the list and detail queries repairs a missed socket event without refetching every query on focus.

## Risks

- A model may emit invalid Mermaid: the source and error are shown instead of a diagram.
- Mermaid's `securityLevel` is process-global once initialized; the map and the final review are separate routes, so they do not render together.
